# Kivori Spec Kit quality gates — repository tooling

Resolves **T138** (Phase 18 convergence finding, gap type `unrequested`).

The `kivori-gates` Spec Kit extension is **repository-wide developer tooling with its own lifecycle**. It is
deliberately **not** part of Feature 001's specified scope: it traces to no FR, SC, plan touch-point, or
feature task, and no Feature 001 acceptance criterion depends on it.

- Source of truth: `tools/spec-kit-extensions/kivori-gates/` (manifest, five commands, config template,
  README, 161 validators).
- Installed payload and hook registry (`.specify/extensions/`, `.specify/extensions.yml`) and the agent
  command registrations (`.claude/skills/speckit-kivori-gates-*`) are **generated by the installer**. Do not
  hand-edit them; run `specify extension add tools/spec-kit-extensions/kivori-gates --dev --force`.
- The installer's network catalog cache (`.specify/extensions/.cache/`) is gitignored.
- Developer usage, compatibility findings for the installed Spec Kit version, and troubleshooting live in
  `tools/spec-kit-extensions/kivori-gates/README.md`.

Versioning is independent of Feature 001: the extension carries its own semantic version in
`extension.yml`, and changing a gate does not change feature scope or acceptance.
